# 代理、SSH与花生壳迁移

## 原机网络基线

Ubuntu amd64，ens33 使用DHCP，当前172.16.61.128/24，默认网关172.16.61.2。旧Mac宿主机HTTP代理为 http://172.16.61.1:7890 。迁移后这些地址都可能变化，按 ip -br address、ip route 和 Windows VMware虚拟网络编辑器核对，不能照抄旧IP。

## 三层代理分别配置

1. 交互终端：旧 ~/.bashrc 明确设置 http_proxy 和 https_proxy，均为上述HTTP代理；即使访问HTTPS，地址也使用 http://，由代理完成CONNECT。
2. GPT账号池：systemd不自动继承终端变量，真实 config.yaml（实际为JSON兼容YAML）明确设置 requests.proxy-url。迁移后需要改这一个字段，保留原 management/access/OAuth配置。
3. Mac/Windows宿主机代理软件：Clash规则、订阅与密钥在宿主机，无法从本Ubuntu读取。本仓库仅记录已观察到的服务地址，不包含宿主机完整规则。迁移前从原代理软件导出配置，通过私密渠道保存；Windows端安装并导入本人配置，允许虚拟机所在网段访问HTTP监听端口。

模板见 [shell-proxy.example.sh](../infra/migration/proxy/shell-proxy.example.sh)。不要将SSH、回环健康检查或账号池内部管理请求交给外部代理；设置 no_proxy/NO_PROXY，并在诊断中使用 curl --noproxy '*'。

```bash
# 把地址改成新Windows宿主机在VM网段中的可达地址，不是虚拟机自己的127.0.0.1。
export http_proxy='http://替换为宿主机IP:7890'
export https_proxy="$http_proxy"
export no_proxy='localhost,127.0.0.1,::1'
export NO_PROXY="$no_proxy"
curl --proxy "$http_proxy" -I --connect-timeout 5 https://github.com
```

确认IP/协议/端口后更新账号池真实配置（脚本默认只展示计划，--apply才改文件并保留原其它字段）：

```bash
python3 scripts/migration/configure_pool_proxy.py --url http://替换为宿主机IP:7890
python3 scripts/migration/configure_pool_proxy.py --url http://替换为宿主机IP:7890 --apply
systemctl --user restart gpt-account-pool
```

脚本在仓库外建立私有配置回退副本；不输出Key。代理重启后先验证本地账号池，再做明确的小额真实模型验收。HTTP站点可达不代表供应商授权和地区限制均已通过。Windows防火墙只按所用代理端口和VM网段授权，保持其他规则。

Windows宿主机可访问新VM IP后，在Windows PowerShell保留此SSH窗口：

```powershell
ssh -N -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -L 8088:127.0.0.1:8088 -L 8090:127.0.0.1:8090 -L 8094:127.0.0.1:8094 -L 1455:127.0.0.1:8094 nanshan@替换为VM地址
```

如果Windows只是另一台客户端、VM仍在Mac私有NAT内，则保留Mac作为ProxyJump中转，具体命令见网关账号池指南；迁至Windows本机后一般可直接连接VM，无需旧Mac中转。旧SSH私钥不进仓库，新客户端生成本人密钥并将公钥授权到目标用户。

外网访问网关使用SSH隧道或已配置可信证书的HTTPS反代；仓库已有Nginx示例，但本机尚未配置公网域名/证书与80/443入口。UFW实际规则因需要管理员密码未读取，不把ufw.service enabled当作规则生效证据。

## 花生壳真实状态与重建

原机dpkg安装 phddns 5.3.0。安装包在 downloads/installers/phddns/phddns_5.3.0_amd64.deb，SHA-256见artifacts.json。关键路径：

- /usr/bin/phddns：厂商管理命令；/usr/bin/phdaemon：启动包装脚本。
- /usr/bin/phtunnel、/usr/bin/phddns_mini_httpd：实际进程。
- /etc/phtunnel.json：设备身份/绑定状态，按敏感文件处理，真实内容不上传。
- /var/log/phddns/phtunnel.log：厂商运行日志；可能含设备/连接信息，按私有资料保管。
- /etc/init.d/phddns_service：SysV兼容启动；systemd生成的同名单元不是完整运行事实来源。

本次实测 systemd phddns_service.service 为 inactive/dead，但 phdaemon、phtunnel、phddns_mini_httpd 三进程存在，16062仅回环监听。因此仅确认进程在运行，未验证账号绑定、公网域名/端口、当前云端映射和手机/外网连通性。

新机器推荐安装厂商包并重新激活绑定：从旧机受控复制安装包并校验，或从[官方客户端下载](https://hsk.oray.com/download)取得适配当前平台的版本。厂商新版可能改变操作方式，应按官方说明操作。

```bash
sudo dpkg -i /受控安装包路径/phddns_5.3.0_amd64.deb
sudo phddns status
# 需要本人查看设备管理页面时，先建立只限本机的SSH转发：
ssh -N -L 16062:127.0.0.1:16062 nanshan@替换为VM地址
```

使用本人浏览器/厂商控制台完成设备绑定、套餐和映射；不要把SN、设备密码或远程访问凭据复制到GitHub。若选择保留 /etc/phtunnel.json 的旧设备身份，须停旧机后再在新机恢复，由管理员核对权限、版本和厂商支持情况，避免两个实例共享设备身份。

在厂商控制台逐项记录并核对：设备、协议(TCP/HTTP/HTTPS)、公网域名/端口、内网目标IP与端口、访问控制和证书设置。账号池8095与设备管理16062保持本机管理范围。最终从真正的外部网络测试映射目标，再登记为穿透可用。

参考：[贝锐Linux客户端教程](https://sunlogin.oray.com/news/11630.html)、[PHTunnel本机管理接口说明](https://developer.oray.com/phtunnel/common)。
