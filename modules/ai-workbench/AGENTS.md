# 项目开发规则

- 遵循 /home/nanshan/AGENTS.md 及 /home/nanshan/workspace/docs/虚拟机目录与存储规范.md。
- 首次开发先填写 README.md、docs/开发计划书.md 的目标、技术栈、路径和验收标准；关键未知项在相关实现前解决。
- 查看已有代码和依赖后再选择实现方式，不因模板目录而改造已建立的框架结构。
- 项目专用脚本、说明和部署定义留在本项目；运行数据放项目计划中登记的外部数据目录。
- 配置示例和锁文件纳入版本控制，真实凭据与依赖目录排除。修改配置键时同步更新示例和运行说明。
- 按变更风险执行必要验证；交付时更新计划、实际命令、验证结果和已知限制。
- 服务部署与数据恢复遵循 docs/运行与维护.md；模板中的“待填写”不能当作已验证步骤。

- 访问控制以access.py及来源后端为准；新结果、任务、引用、通知和记忆须继承全部来源项目依赖，不得以管理员身份或缓存绕过私人内容与实时撤权。
- 改动权限/外发/记忆/桥接时运行相关专项；TestDock联动通过HTTP授权接口，不跨服务直接读写生产业务库。生成草案必须经人工应用，不能自动运行测试。
- 模型配置默认关闭；测试使用本地协议服务和独立库。未提供真实密钥时保留待联调状态，不用模拟结果描述真实模型效果。
