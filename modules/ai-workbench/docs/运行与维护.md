# 运行与维护

## 用户入口

AI工作台8090，TestDock8088，项目与账号相互独立；初始凭据见各服务config/initial-admin.txt，不写入文档。首次登录修改密码。管理员可创建账号/本地项目，再添加成员；非管理员的项目管理员也可选择现有账号添加成员。

TestDock右上角账户设置→连接AI工作台→复制60秒绑定码；登录AI工作台→模型与设置→绑定当前账号。绑定后自动同步本人全部可见TestDock项目；设置页可立即同步用例/套件/环境公开配置/运行概览，后台约5分钟同步一次。成员在来源平台维护。用户委托30天有效，可在TestDock账户设置撤销；过期/撤销后重新绑定。来源服务断开时相关项目和内容隐藏，不使用旧授权缓存。

选择全部可访问项目或单项目→上传文件/添加知识文本→任务页查看处理→低置信度OCR在详情复核→本地检索。资料范围可选private/project/workspace，内容受全部来源依赖约束；个人会话默认私有。讨论可提及成员、回复；通知只对本人可见。

记忆先创建候选，个人记忆由本人确认，项目记忆由项目管理员确认；共享个人记忆时重新审核。来源变更会标记失效，审核前必须重新整理。删除后停止检索并清除索引及当前原文件，备份按人工保留策略处理。

## OpenAI / DeepSeek

当前无真实API密钥，两项预置均关闭。管理员在模型与设置中填写自己的API密钥、可用模型ID并启用。OpenAI Base URL为https://api.openai.com/v1；DeepSeek为https://api.deepseek.com，预置deepseek-flash（按2026-11-15官方文档）。OpenAI预置gpt-4.1作为可编辑示例，应使用当前账号可用模型。密钥不回显，留空保留原密钥。可配置其他OpenAI兼容内网服务；可信内网标记须管理员确认，不能把外部服务标成内网来绕过资料策略。

外部模型使用前需项目管理员允许项目外发，资料本身也需允许（详情中由项目管理员调整）；祖先来源有任何限制则拒绝。通过授权桥接导入的新TestDock脱敏报告沿用当时的项目策略。只选择获准资料，查看来源引用，截图/原文件不直接发外部模型。AI问答、失败分析、记忆提取、草案均在任务页跟踪；模型超时不会自动重试计费请求。当前无模型价格配置，仅展示Token，日额度在真实settings.json的daily_tokens中调整并重启服务。

TestDock报告中“AI分析”打开工作台并导入本人可见的只读运行证据；先绑定账号。生成草案后查看全部步骤和变量，确认应用仅新增用例，不启动测试。目标项目必须包含草案全部来源依据；生成跨项目草案时应重新按单项目生成后再应用。

项目卡片可订阅本人测试失败通知，默认关闭。项目管理员可启用自动失败分析并选择模型；外部模型需事先授权项目外发。每个失败运行去重处理，执行人失权后停止；旧结果也按来源权限隐藏。

## 服务启停

```bash
systemctl --user status ai-workbench.service ai-workbench-worker.service
systemctl --user restart ai-workbench.service ai-workbench-worker.service
journalctl --user -u ai-workbench.service -u ai-workbench-worker.service -n 100 --no-pager
curl -fsS http://127.0.0.1:8090/api/v1/health
```

app/config/data/logs分别位于workspace/services/ai-workbench。API和worker日志用用户journal；SQLite、任务、原文件和索引在data；真实JSON、主密钥及桥接密钥在config。进程组ai-workbench.slice配置内存1280MiB、CPU一核配额，worker低优先级。当前用户服务及Linger状态以工作区软件与服务清单为准。

配置通过AIWORKBENCH_CONFIG指定JSON，默认服务config/settings.json，不读.env。源码在projects/ai-workbench，.venv隔离安装，requirements.lock锁定所有实际包。开发使用data/ai-workbench/dev下另一份配置，不能用服务库运行自动化测试。8093仅用于临时开发QA，结束后停止。

公开嵌入/OCR模型位于tools/ai-models。scripts/prepare_models.py只下载公开模型，不发送项目资料；运行语义检索只读本地缓存。RapidOCR模型版本由锁定的3.10.0选择，当前为PP-OCRv6小检测/识别与移动方向分类器。模型摘要记录在tools/ai-models/manifest.json。图片上限1600万像素，单文件20MiB、PDF100页，压缩Office展开上限100MiB，文件类型白名单，低于3GiB可用空间暂停新导入。

## 部署、备份和回退

```bash
cd /home/nanshan/workspace/projects/ai-workbench
PYTHONPATH=src .venv/bin/python scripts/deploy.py
PYTHONPATH=src .venv/bin/python -m aiworkbench.cli backup
PYTHONPATH=src .venv/bin/python -m aiworkbench.cli verify --snapshot /home/nanshan/workspace/backups/ai-workbench/快照名 --output /home/nanshan/workspace/tmp/ai-workbench/restore-唯一名称
```

部署先创建独立备份、校验新app，将旧app移入archives/ai-workbench，再安装用户单元并检查API/worker健康。只替换app，不覆盖config/data。备份包含一致性SQLite、密钥、真实配置、原文件、源码与锁文件，排除.venv/模型二进制/普通日志。需要准确停止点时先停止API和worker再备份。

验证在全新tmp目录恢复，核对SHA-256、SQLite integrity和加密记录；restored-settings.json可隔离启动检查。正式恢复前停止写入并备份当前状态，使用verify产生的隔离恢复副本恢复数据库/原文件与配套密钥并核对路径。验证副本会清空会话与来源委托、关闭模型/自动化/订阅、取消未完成任务，并仅保留首位有效管理员活跃；恢复后需人工核对本地成员、重新启用用户/模型并绑定来源。恢复时重新复核来源权限，未知模型计费状态和中断任务不重放。回退程序用已归档app及匹配锁文件，数据库恢复另行明确恢复时点，不能覆盖发布后新数据。备份及历史删除由人工执行，未配置异机备份或自动清理。

TestDock新增config/ai-bridge.key须与AI工作台config/testdock-bridge.key配套。两端备份均保留桥接密钥；恢复后不匹配会拒绝连接。TestDock的成员和报告权限始终在其后端校验。
