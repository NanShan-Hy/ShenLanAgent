演示目标位于 127.0.0.1:8091（开发）和 127.0.0.1:8092（测试），只供本机执行器使用。演示用例执行真实浏览器与 HTTP 请求。添加自己的业务环境即可复用或创建业务用例。

## 服务启停与日志

用户单元位于 `~/.config/systemd/user`，源文件在项目 deploy。

```bash
systemctl --user status testdock.service testdock-worker.service testdock-demo-dev.service testdock-demo-test.service
systemctl --user restart testdock.service testdock-worker.service
journalctl --user -u testdock.service -u testdock-worker.service -n 100 --no-pager
curl -fsS http://127.0.0.1:8088/api/health
# 停止全套：
systemctl --user stop testdock-worker.service testdock.service testdock-demo-dev.service testdock-demo-test.service
```

健康响应为 status=ok、worker_online=true，检查数据库与 worker 心跳；目标连通性用实际用例验证。当前Linger=yes且用户服务已enabled；整机重启/注销实测尚未执行，维护状态以本机软件服务清单为准。

## 配置与开发隔离

默认读取 `/home/nanshan/workspace/services/autotest-platform/config/settings.json`；`TESTDOCK_CONFIG` 可指定另一份 JSON。示例在 config/settings.example.json。主密钥必须与数据库配套保存；丢失后无法解密环境凭据和快照，切勿删除已有密钥后启动服务。

run_timeout 默认 900 秒，步骤独立超时 1–120 秒、默认 15 秒；min_free_bytes 默认 3 GiB。browser_library_path 只影响 Chromium 子进程，不修改系统库。secure_cookie=false 用于当前局域网 HTTP；HTTPS 部署应设置 true。当前无公网域名、HTTPS 代理或公开托管。

开发使用独立配置及数据，目录 700、真实文件 600；不要使用服务数据库。示例：

```bash
cd /home/nanshan/workspace/projects/autotest-platform
export PYTHONPATH=src
export TESTDOCK_CONFIG=/home/nanshan/workspace/data/autotest-platform/dev/config/settings.json
.venv/bin/python -m testdock.cli init
.venv/bin/python -m uvicorn testdock.app:app --factory --host 127.0.0.1 --port 8089
# 另一个终端设置相同变量，再启动 worker：
.venv/bin/python -m testdock.worker
```

init 只在空库创建随机管理员，不重置已有账号。开发环境需要浏览器库时将示例配置的 browser_library_path 加入真实开发配置。上述 export 仅用于开发终端；生产服务使用单元中的明确路径。pytest 自动创建 tmp 下独立库及目标服务器。

## 部署与回退

完成 README 检查，确认可用空间至少 3 GiB，再执行：

```bash
cd /home/nanshan/workspace/projects/autotest-platform
PYTHONPATH=src .venv/bin/python scripts/deploy.py
```

脚本先一致性备份，停止 web/worker，将旧 app 保存到新的 archives/autotest-platform/UTC时间，然后复制并校验程序、安装用户单元和启动。config/data 保留。版本与源文件哈希在服务 app/release.json。服务依赖项目 .venv，删除或更换该环境前先停服务并准备匹配依赖。当前数据库 schema=1，无自动迁移。

程序回退：停 web/worker → 将当前 app 另存新归档 → 从对应历史 app 复制旧程序 → 按其锁文件准备匹配依赖 → 检查配置兼容 → 启动并验收。不要覆盖运行后新增数据；数据库回退须另行明确恢复时点和新增数据处理方法。

## 手动备份与恢复

```bash
cd /home/nanshan/workspace/projects/autotest-platform
PYTHONPATH=src .venv/bin/python -m testdock.cli backup
# 使用上一步输出的真实快照路径；目标必须为全新 tmp 子目录：
PYTHONPATH=src .venv/bin/python scripts/verify_backup.py /home/nanshan/workspace/backups/autotest-platform/快照名 --output /home/nanshan/workspace/tmp/autotest-platform/restore-唯一名称
```

快照含 SQLite 一致性副本、master.key、settings.json、源码/文档/锁文件、已结束运行附件及 SHA-256 清单。活动任务附件不复制；恢复数据库中 running 任务会被 worker 标记异常，queued 继续执行。需要准确停止点时先停 web/worker 再备份。验证脚本在全新临时目录恢复，检查哈希、SQLite integrity 和全部加密记录，保存 verification.json 与可用于隔离启动的 restored-settings.json。

正式恢复：停止写入服务，先备份当前状态，验证快照，再恢复数据库和 runs 到服务 data，恢复配套密钥到 config，根据当前路径人工核对 settings.json。目录 700、文件 600，启动后检查健康、登录、资产及报告。源码部署不能覆盖 config/data。

备份保留、删除历史附件和日志由人工执行。同盘备份仅用于操作回退；未配置异机备份、自动备份或自动清理。

## Cron 和 CI

表单选择套件、环境、五段 Cron、IANA 时区与启用状态。`0 9 * * 1-5` + Asia/Shanghai 表示工作日北京时间 09:00。相同计划 queued/running 时跳过重叠触发；停机超过一分钟的过期触发不补跑；创建人失权会停用计划并记录原因。

项目管理员在“成员与集成”创建有期限的 CI 令牌，明文只显示一次。保存到 CI 凭据并注入 TESTDOCK_CI_TOKEN，不放进源码、参数或日志。脚本仅需 Python 标准库，可在能访问虚拟机的 Jenkins/GitLab runner/GitHub self-hosted runner 使用：

```bash
python3 scripts/ci_run.py --url http://172.16.61.128:8088 --project 1 --suite 1 --environment 2 --idempotency-key build-唯一编号 --junit artifacts/junit.xml
```

返回 0 全通过，1 失败/异常/取消，2 请求失败或等待超时；超时请求取消。CI 收集生成的 JUnit XML，各环境分别调用可组成环境矩阵。公网托管 runner 通常不能直接访问私网 VM，应使用已有内网 runner。

提交 `POST /api/ci/projects/{project}/runs`，JSON `{"suite_id":1,"environment_id":2}`，头 `Authorization: Bearer <CI凭据>` 与 `Idempotency-Key: <构建编号>`。查询 `GET /api/ci/runs/{id}`；取消 `POST /api/ci/runs/{id}/cancel`；JUnit `GET /api/runs/{id}/junit.xml`。同令牌同键同参数返回原任务，不同参数 409；未结束任务导出 JUnit 返回 409。ID 以实际页面/接口为准。

## 维护边界

登录会话 12 小时，修改密码注销旧会话。普通变量、用例正文属于项目可读资产，请用敏感变量引用真实凭据。接口日志按字段及已知敏感值脱敏；截图和 Trace 可含页面、网络及业务数据，按项目权限访问，下载后也须受控。Trace 可使用 .venv/bin/python -m playwright show-trace 文件路径 查看。

默认单 Chromium 执行队列，角色面向可信小团队；测试人员可以配置目标地址并通过用例使用环境凭据。附件、日志和数据库持续占用磁盘，按本机容量规范检查，不自动清理。需要高并发、分布式或多租户时先调整计划及迁移方案。

## 1.1 资产迁移、历史与批量回归

详细步骤与边界见 [业务接入手册](业务接入手册.md)。已有 1.0 配置、数据库 schema=1、账号及报告继续使用，不需要迁移。依赖锁文件不变。部署脚本会携带 examples 目录，备份也包含可复用示例。

管理页面新增“接入指南”。用例页可上传/粘贴 TestDock 资产包或 OpenAPI JSON，解析预览并勾选后，先预检再确认导入。导出不含环境敏感值，命名凭据字段清空；分享前仍要检查普通变量/正文。原快照重跑用于复现历史；按最新配置重跑读取当前用例版本与原环境当前配置，删除的用例/环境会报资源不存在。

API 新增（均要求登录会话，写入请求使用 X-Requested-With: TestDock，按项目 tester 授权）：

| 路径 | 用途 |
| --- | --- |
| GET /api/projects/{id}/assets/export | 下载可迁移资产包 |
| POST /api/projects/{id}/assets/import | JSON 为 bundle、prefix、dry_run；dry_run 默认 true，false 才写入，事务全量回滚 |
| POST /api/projects/{id}/openapi/preview | document 为 OpenAPI JSON；返回可选用例、待配置变量及告警，无自动网络抓取或执行 |
| POST /api/projects/{id}/runs/matrix | suite_id 或 case_ids，environment_ids（最多20个），原子提交并去重环境 |
| POST /api/runs/{id}/rerun | failed_only 默认 true；use_latest 默认 false，为 true 时按最新配置生成快照 |
| GET /api/projects/{id}/runs/search | q/status/environment/trigger/since/until/page/page_size；返回 items/total/counts；时间为 Unix 秒，单页最多100 |
| GET /api/projects/{id}/examples/sales | 下载无敏感值的销售模板，项目 viewer 也可下载 |

请求实际读取上限 2MiB（包括无 Content-Length 的流式请求）；导出上限略低于 2MiB，保证可再次导入。单包最多1000用例、100套件、100环境。HTTP 解压后响应上限5MiB；超限本步骤标异常，已停止读取。gzip JSON 和原始响应头断言仍可正常使用。页面导航使用步骤设定的超时。

历史查询覆盖所有保留运行，原先 GET runs 保留最近200条行为用于概览与旧客户端。新增的查询和导入接口当前使用浏览器会话，CI Bearer 入口仍按原约定逐个环境提交；不同环境应使用不同幂等键。

1.1部署增加启动健康检查：等待API、worker心跳及两套演示目标可用后才报告成功；未通过时非零退出，保留前置备份与旧app，按本文件回退，不声称自动回退。

## AI授权桥接

桥接程序在src/testdock/ai_bridge.py。账户设置→连接AI工作台生成60秒、单次使用的随机绑定码；登录8090设置页粘贴绑定。用户委托有效30天，重新绑定使该账号旧委托失效；“撤销AI委托”即时吊销。服务HMAC密钥不能代替用户委托；所有来源查询、报告和应用操作均校验当前来源账号/角色。私有模型会话在AI服务独立保存。

桥接使用config/ai-bridge.key（600），须与AI服务config/testdock-bridge.key一致，密钥已纳入本平台手动备份。新增ai_codes、ai_delegations、ai_nonces三个辅助授权表，原业务schema=1及环境、报告不变。更新前备份；verify_backup.py会撤销恢复副本中的AI委托并清空绑定码；正式恢复旧来源库时也应撤销ai_delegations并重新绑定，避免恢复旧委托，配套密钥需同时核对。恢复验证副本只做隔离检查，不启动执行worker。

服务端接口/api/integrations/ai/{bind,context,assets,evidence,failures,apply}均要求签名，除bind外还要求来源签发的有效用户委托。assets仅导出脱敏数据；apply仅允许tester以上新增经本平台校验的用例，不入执行队列。报告AI链接为独立工作台入口，详情见AI项目运行说明。


## 1.2 部署、通知执行器和恢复

当前功能见[每日任务与通知](通知与每日任务.md)。用户级增加testdock-notifier.service；/api/health增加notifier_online，后台心跳独立于模型和测试进程。API、worker、notifier及两套演示目标按部署脚本一起管理；notifier内存限制160MiB，使用用户journal。

升级先确认没有排队/运行测试，构建并校验暂存程序，再停写API/worker/notifier，创建独立一致性备份，然后迁移schema1→2并替换app。部署脚本若队列未清空会停止部署；不终止正在执行的业务测试。旧app在archives，发布记录release.json含来源与哈希。真实配置新增可选report_base_url，缺省为当前局域网8088地址；不得含嵌入凭据。

常用检查：systemctl --user status testdock.service testdock-worker.service testdock-notifier.service；日志journalctl --user -u testdock-notifier.service。每日执行依赖机器开机、时钟及网络；用户要求注销及重启后运行，Linger与用户单元实际状态以本机清单为准。整机重启和注销涉及共享会话，未实际测试时不得描述为已通过。

恢复验证脚本支持schema1/2快照，检查通知渠道/载荷解密，并在副本中暂停全部计划、关闭通知渠道、取消排队/运行测试及待发通知，撤销旧AI委托；恢复副本不启动worker/notifier。正式恢复需重新核对计划、接收目标、成员和密钥后再启用，不能自动重放业务测试或未知通知。旧1.1程序不支持schema2，回退必须使用匹配schema的数据库并明确恢复时点，不能覆盖发布后新数据。

当前未配置真实推送密钥，新增渠道列表为空，不会对外发送演示或历史消息。后续由管理员在页面配置并明确试发；接口受理和手机送达分别验收。当前AI生成模型仍未启用。
