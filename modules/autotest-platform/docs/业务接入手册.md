# 通用项目业务接入手册

TestDock 通过项目、环境、步骤、变量和断言组织测试，适用于销售、供应链、后台管理等 Web 与 HTTP 业务。平台核心不包含行业销售逻辑；[化工品销售模板](../examples/chemical-sales.json) 提供可执行的业务链路示例。移动端仍暂缓。

## 从一个小回归开始

先为目标系统创建独立项目，添加测试环境的 Web/API 基础地址。基础地址可以含 API 路径前缀，相对步骤路径附加于此前缀。使用普通变量表达用户名、业务数据和预期值，使用敏感变量表达密码/Token；步骤引用写成 `{{username}}`、`{{password}}`。完整变量引用保留数字/布尔/对象类型，字符串中的引用转换成文字。URL 路径变量采用可安全放入路径的值；复杂转义请在变量中提供已编码内容。

选择一个可重复的业务流程：登录 → 查询商品 → 创建报价 → 提交订单 → 查询核对。把需要共享会话、Token 或提取值的步骤放在同一用例中。各用例独立会话、浏览器和变量，不能依赖另一个用例的临时提取值。HTTP会话与浏览器会话分别管理，二者通过提取变量共享显式数据，不自动同步Cookie。

HTTP 响应提取使用 JMESPath，如 `token`、`items[0].sku`、`data.id`，命名 `session_token`/`sku`/`order_id`；Token 勾选敏感值。后续步骤的 Headers 填 `{"Authorization":"Bearer {{session_token}}"}`，JSON 请求体引用 `{{sku}}` 等变量。断言不仅检查 HTTP 状态，也核对环境、金额、ID、状态和关键字段。

Web 优先使用稳定的 data-testid、表单标签或可见文字定位；用自动等待和断言等待业务状态，不使用固定睡眠。多个输入与提交步骤可与接口步骤混合，提取的值在当前用例内共享。

## 使用已有接口文档

在用例页选择“导入”，上传或粘贴 OpenAPI 3.0/3.1 JSON，点击解析，核对待配置变量和告警，勾选需要的操作，再预检和确认。仅创建用例，不自动调用业务接口。OpenAPI 字段处理依据 [官方 3.1.1 规范](https://spec.openapis.org/oas/v3.1.1.html)，当前实现覆盖常见操作子集：

- 路径与操作参数（操作级覆盖同名路径级参数）、本地 JSON Pointer 引用、JSON/form 请求体、简单 schema 示例/默认值。
- 路径参数变成 path_变量，其他缺失数据使用 query_/header_/body_变量；Bearer、Basic、OAuth2 Bearer、header/query API Key 生成鉴权模板。Basic 值需提供 Base64 编码的账号:密码，OAuth2 令牌需自行获取。
- 状态断言取文档的明确 2xx 成功码，未声明时默认200并提示核对。鉴权备选默认使用第一组，需结合实际接口修改。

外部引用、循环/深层/组合 schema、cookie 鉴权、文件上传、复杂参数序列化、OpenAPI 2/YAML 均不自动转换；预览会提示手工配置或跳过无法生成的操作。schema 示例用于生成草稿，执行前必须调整为真实测试数据。目标服务器地址从环境配置，文档 servers 不自动覆盖环境。

## 迁移资产与团队协作

资产 JSON 使用 testdock-assets-v1 格式，包含用例、套件的相对引用和环境模板。导出会移除环境敏感值、清空命名凭据字面值，并保留变量引用；用例正文和普通数据仍应人工检查。导入支持名称前缀；同名资产不覆盖，错误不产生部分写入。预览不会写库，确认后事务写入。单包限制见运行说明。

导入环境后按提示重新添加敏感变量。测试人员可以编辑/导入/执行，项目管理员额外管理成员及 CI 令牌，只读成员查看资产和报告。项目测试人员有使用环境凭据及配置被测地址的能力，角色用于可信团队协作。

## 多环境回归与失败修复

把流程用例加入套件，主环境选择开发，勾选其他环境如测试/预发，一次提交多个独立运行。系统逐个运行，保留每次环境与用例快照，不因运行中编辑资产而变化。历史页按状态、环境名称、触发方式、关键字及时间筛选并分页；时间输入按浏览器本地时区。

失败报告中，“重跑原快照”与“复现未通过快照”复用旧版本和旧环境，适合复现；修复用例或环境后，选择“按最新配置重跑未通过”。后者只选原任务未通过或未执行用例，以当前版本和当前环境生成新快照。若原用例/环境已删除，会拒绝提交，可从用例页重新选择资源。所有历史结果保留。

稳定后配置 Cron 和时区，或从流水线调用 scripts/ci_run.py，每个目标环境单独调用并使用不同构建幂等键，收集 JUnit XML。写入型测试应使用受控测试环境、唯一业务数据，并在业务流程中规划相应撤销/清理接口；平台不隐式删除目标业务数据，也不自动重放中断的已开始任务。

## 运行销售示例

建议建立独立“销售流程练习”项目，在接入指南下载模板，导入后给两套环境补充公开演示敏感变量 `password=demo-pass`，其余变量和本地目标地址已在模板。运行“销售核心流程回归”，勾选两套环境，将执行两套 Web/API 流程。

商品与价格是虚构测试数据：工业乙醇 ETH-99，690分/kg，数量2时断言金额1380分。接口顺序：session → products（提取SKU）→ quotes（提取quote_id）→ orders（提取order_id）→ order详情（验证报价、金额、状态）。页面在 /sales 完成相同业务。演示报价和订单仅存在目标进程内存，重启清空；平台报告和附件持久保留。用于其他业务时修改地址、字段、业务数据、鉴权和断言即可。
