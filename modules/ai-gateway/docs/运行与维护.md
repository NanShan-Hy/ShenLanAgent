运营管理→会话与调度提供策略、当前会话明确调整/迁移、问答/摘要查看、会话与附件分别预览清理、媒体能力及容量设置。身份模式配置在应用默认规则；共享网站Key应使用外部用户模式，后端传真实登录ID和授权版本，权限变化时换版本，避免旧缓存越权。详情见[网页会话与MCP接入](网页会话与MCP接入.md)。

## 0.6 请求审计与加密正文

运营管理→请求审计，可按平台账号、空间、应用、Key、模型、状态、阶段、时间和编号查询；账号与配额的每名用户提供“查看请求”。查看问答按本轮问题/模型回答/工具过程分区、分页加载。已保存内容可能含用户业务资料，仅运营管理员可读；读取及清理写入操作审计。日志不保存正文或认证资料。

记录设置初始开启，正文1GiB、手动清理；关闭后仍记录元数据。达到上限、低于原磁盘保护阈值或写入失败时，模型调用照常，正文标为部分缺失/未采集。未完整返回的Chat工具参数暂存上限2MiB，超出只影响内容记录。正常调用状态与内容状态独立，采集失败不自动进入资金待对账。模型/账本本身不可用仍执行原失败保护。

正文在现有data/gateway.sqlite3的request_capture_chunks加密存储，依赖原config/master.key，无新明文文件；最大约64KiB Unicode安全片段，读取每页最多8块。数据库目录700、数据库与主密钥600；备份自动包含这些密文，verify逐块解密并检查归属和容量账目，恢复副本仍禁用上游和Key。主密钥不能随意替换。

手动清理先选择用户/截止时间预览，每批最多100条，执行时校验选择摘要，以128块小事务删除正文；请求索引、Token及账本保留。已有备份独立手动管理；SQLite页用于复用，不自动VACUUM或自动删除历史。

新增后台接口为/admin/request-audits及其详情、content、options、cleanup/preview、cleanup，和/admin/request-audit-settings（均带/api/v1前缀）。推理接口返回X-Gateway-Trace-Id，原X-Request-Id保留其财务请求语义。幂等重复请求的审计行关联原单，本次费用为0。升级schema4→5只增加审计结构及历史元数据，历史正文显示未采集。

## 入站429配额诊断（0.5.3）

入站配额不满足时尚无财务请求；0.6起请求审计另有入站拒绝记录，不应凭用量页为空判断未到达网关。查询`journalctl --user -u ai-gateway.service --since '10 minutes ago' --grep 'quota_rejected|context_rejected'`，配额日志仅含固定scope（platform/tenant/user/application/key/package/upstream_group）、dimension及used/requested/limit整数，上下文日志仅含input/output/limit整数；不记录正文、Key和账号标识。Token的requested是输入预算与最大输出之和，包含工具和系统上下文；它不是已消费Token或扣款。0.5.4起OpenAI与本机GPT账号池使用离线分词估算，资金仍沿用字节上界；详见接入与额度。按实际策略及业务需求调整额度；程序不会自动提额、充值或重放请求。这些日志只覆盖本地拒绝，不代表代理或上游429的诊断结果。

0.5.4的公开词表与许可证在src/aigateway/token_data，随app部署/清单校验及备份，不放服务config，不含用户内容。tiktoken0.14.0及其依赖仅装项目.venv，requirements.lock固定版本。部署脚本在进入维护模式前离线校验/预载词表；服务启动也会预载。缺失、损坏或锁依赖未安装时先修复部署，不让运行时联网下载词表。双词表缓存仅包含公共编码表，不缓存请求；分块避免重复长字符串引发无界分词耗时。

## 手动备份与隔离恢复

```bash
PYTHONPATH=src .venv/bin/python -m aigateway.cli backup
PYTHONPATH=src .venv/bin/python -m aigateway.cli verify \
  --snapshot /home/nanshan/workspace/backups/ai-gateway/快照名 \
  --output /home/nanshan/workspace/tmp/ai-gateway/恢复-唯一标识
```

backup支持`--root`指定其他目标。先检查空间，创建唯一快照，SQLite backup API获取一致性副本；保存主密钥、真实参数、已安装用户单元（存在时）、源码与锁文件/Git元数据，排除依赖、缓存、普通日志及真实源码配置。SHA-256清单记录快照内容；所有目录700/文件600。

verify要求全新目标，核对文件哈希、SQLite integrity、上游凭据解密和账本。0.2工具可将schema1旧快照在隔离副本升级到schema2。只修改恢复副本：关闭模型/池/上游、撤销Key、删除会话/邀请码、追加释放未完成冻结的账本，取消旧诊断/尝试租约，仅保留首位运营管理员活跃并生成config/recovery-admin.txt。原服务数据不修改，不启动任何模型调用。

## 对外访问

默认仅本机监听。在客户端使用README中的SSH隧道即可访问UI和API。已有8088/8090服务不受影响。

公开入口可由单独管理的Caddy/Nginx提供HTTPS反代，转到127.0.0.1:8094，保留外部Host请求头，关闭SSE缓冲并设置大于路由超时的读取超时。OAuth回调及含授权参数的访问日志应关闭或脱敏；保留回调响应的no-store及no-referrer头。将public_url改为实际HTTPS地址后重启，使Cookie和文档使用正确地址。当前不安装/启动反代、不修改DNS或防火墙，公网HTTPS未实测。不要把服务改为公网明文HTTP来传送Key。

当前不信任任意X-Forwarded-For，IP白名单按连接IP判断；通过反代时看到代理IP。公开场景若需真实客户端IP限制，应先部署可信代理来源及转发头策略再开放该功能，不能依赖任意客户端自报IP。

公开注册为独立开关，public_url必须HTTPS；默认邀请注册。在线支付首期只有契约/禁用响应，需实现对应商户接口、回调验签、订单幂等、退款及对账验收后才能启用。0.3的ChatGPT账号池已实现适配模块，商业集成默认关闭；真实开通按[账号池接入](ChatGPT账号池接入.md)配置供应商签发的客户端、HTTPS回调和持有人授权，不能改数据库或勾选声明来代替真实接入资格与联调。

0.3升级schema2→3，新增商业OAuth配置、稳定VM主机ID、加密的一次性授权事务、账号授权/续期租约及额度观察。schema1/2可在新版本升级，旧程序不支持schema3；跨版本回退必须保留新流水并匹配数据库，不能只恢复旧app。快照manifest同时记录软件版本和实际数据库版本。恢复副本会禁用商业接入、清除账号令牌与授权事务、更新主机ID，不撤销原生产授权。

## HTTPS代理配置准备（0.3.1）

提供deploy/nginx-site.conf.template、scripts/render_https_proxy.py和未安装的用户服务样例deploy/ai-gateway-proxy.service.example。模板保留外部Host，清除客户端转发头，不重试上游请求，关闭请求/响应缓冲、代理临时文件、压缩和HTTP请求日志。SSL/TLS由入口处理，后端保持127.0.0.1:8094；目前不依据转发头识别客户端IP，Key的IP策略仍看到代理连接IP。

以下为待填真实域名和证书的示例，不能把示例域名登记为自己的回调。证书、私钥应先由入口维护者准备，私钥600、所在config/tls目录700，不进入Git。脚本只生成配置，不改public_url、不安装或启动代理，同名输出会停止。默认只绑定127.0.0.1:8443，实际对外地址、端口、DNS及网络映射需按真实入口确认。

```bash

PYTHONPATH=src .venv/bin/python scripts/render_https_proxy.py \

/home/nanshan/workspace/tools/nginx/1.24.0-2ubuntu7.19/usr/sbin/nginx -t \

  -c /home/nanshan/workspace/services/ai-gateway/config/nginx.preview.conf -e stderr
```

独立配置前台运行，进程日志走stderr（用户服务时为journal），PID及临时目录在data/proxy。维护者如需文件日志，应放services/ai-gateway/logs且继续禁止记录OAuth参数、请求体、Cookie及Authorization。已有Nginx入口可使用--site-only生成http作用域下的upstream/server片段；不要将完整独立配置直接放进sites-enabled。`nginx -t`只验证语法及证书/私钥可加载，不证明域名归属、证书可信或真实公网可达。

对外启用前，将监听接口与端口、实际HTTPS public_url、证书名称和供应商登记回调逐项核对。模板不会自动开放80/443、申请证书、修改DNS/防火墙或安装样例服务。用户级代理使用未受特权限制的高端口；常驻配置按本机用户systemd规范执行。真实公网域名和商业客户端尚未提供，当前生产代理未启用。

浏览器或SDK访问本机/内网测试域名时，检查其代理绕过规则；隔离验收仅对测试域名强制直连，不修改主机代理设置。验证依据：[NGINX代理指令](https://nginx.org/en/docs/http/ngx_http_proxy_module.html)、[TLS配置](https://nginx.org/en/docs/http/configuring_https_servers.html)、[请求日志关闭](https://nginx.org/en/docs/http/ngx_http_log_module.html)。

## 0.5 统一账号池与回调

当前不再提供旧SIWC商务接入功能，上文0.3配置和恢复说明仅为历史记录。新流程见[GPT账号池配置指南](GPT账号池配置指南.md)。schema1/2/3均可升级至4；旧表通过触发器冻结，旧资源禁用，不删除账本或历史请求。旧版程序不能直接使用schema4；回退使用对应程序、依赖及经过核对的数据库快照，不覆盖新增账本。

自动回调GET /auth/callback复用8094；Windows将本机localhost:1455经SSH转发至虚拟机127.0.0.1:8094。网关以一次性state及原发起会话的当前有效性验证，无需回调浏览器携带门户Cookie。回调后303重定向清除地址栏授权参数，并发送no-store/no-referrer；继续保持Uvicorn和代理的访问日志关闭。不要使用后端is_webui启动绑定0.0.0.0的额外回调服务。

账号授权状态区分等待登录、交换凭据、等待载入和就绪。只有后端saved/adopted为真且账号存在才显示成功；失败只保存阶段、错误码与必要HTTP状态，不保存原始错误、授权码或令牌。多账号使用round-robin、会话保持1h及session-affinity-rebind-on: quota，额外请求重试保持0、每轮凭据尝试1，已发送请求不重放。

## 0.5.1 回调提示与出站代理

回调结果页明确“无需复制地址或再次手动提交”，表单识别结果页并给出独立提示，避免覆盖后台真正失败原因。unsupported_country_region_territory映射为安全地区限制错误码，不保存供应商原文。schema保持4。

本机终端已有http_proxy/https_proxy指向172.16.61.1:7890，账号池systemd进程未继承，直连认证接口只读探测取得HTTP403/unsupported_country_region_territory。按用户确认的代理方式，已在services/gpt-account-pool/config/config.yaml的requests.proxy-url显式使用现有HTTP代理；保留其余配置及内部Key，文件600。服务重启后通过本机管理配置确认值已加载，本机/v1/models健康。不得通过整体替换配置丢失账号/内部Key；本机管理调用继续直连回环地址。真实账号重新登录及实际生成仍单独验证。
